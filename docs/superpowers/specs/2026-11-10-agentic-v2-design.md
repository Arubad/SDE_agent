# Agentic v2: design

## Why
The premium "agent" is a fixed pipeline: router → parallel searches → generate → verify → one retry.
The model never decides what to do next. The repo's evals only cover single-hop questions that one
search answers, and nothing measures behaviour on questions the knowledge base cannot answer or on
hostile content. Ingested YouTube content and retrieved passages are untrusted text fed straight
to the model, and the UI renders model output as markdown (images auto-load), so prompt injection
is a real attack surface.

This work adds three things, each measured:

1. **A real tool-use agent loop** over the existing MCP server, as an alternative premium mode.
2. **Harder evals**: multi-hop questions (two documents needed), unanswerable questions
   (abstention), and trajectory metrics (steps, tool calls, tokens).
3. **Prompt-injection defenses** with a red-team eval reporting attack success rate before/after.

## Non-goals
- No change to the public (Gemini) tier. No eval may call Gemini (free quota is 20 requests/day).
- No new runtime dependencies, no new services, no frontend changes (existing SSE event shapes are reused).
- No multi-turn eval set, no long-term memory, no multi-agent orchestration.

## 1. Agent loop
- New premium mode `AGENT_MODE=loop` (default stays `pipeline` until the eval decides).
- Tools are **discovered from the MCP server** (`list_tools`) and converted to Claude tool
  definitions; an allow-list restricts them to `search_knowledge_base`, `analyze_youtube_video`,
  `get_document`.
- Each turn: Claude Haiku 5.5 (Foundry) streams; every `tool_use` block in the turn runs
  concurrently through the in-memory MCP client; all results go back in **one** user message.
- Passages are returned as `search_result` blocks inside `tool_result`, so the final answer carries
  API-native citations. Citation `search_result_index` counts every search_result block sent in the
  conversation, in order, so the loop keeps that ordered list (duplicates included).
- Budget: `AGENT_MAX_STEPS=4` model turns. On the last allowed turn tools are disabled
  (`tool_choice: none`) so the model must answer.
- The loop replaces router and verifier in this mode (it can refine its own searches).
- If the loop fails with a provider outage, the request falls back to the pipeline.
- History is append-only and assistant content is passed back unchanged (Haiku 5.5 thinking
  blocks must survive).

## 2. Evals
- **v2 question set** (`questions_v2.jsonl`), generated by Haiku and validated programmatically:
  - `multi_hop`: built from two related passages in *different* documents; two verbatim evidence
    quotes, both checked against their passages. Target ≥ 60.
  - `unanswerable`: specific questions on 30 fixed out-of-corpus topics; kept only if a judge says
    the top-8 retrieved passages do not contain the answer. Target ≥ 20.
- **Metrics** per variant (`pipeline`, `pipeline_noverify`, `loop`):
  - multi-hop: correctness, faithfulness (existing judge), **evidence recall** (share of evidence
    quotes present in the passages the generator saw).
  - unanswerable: **abstention rate** (answer states the sources don't cover it) and
    **false-support rate** (does not say so and cites sources anyway).
  - trajectory: model turns, tool calls, tokens, p50 latency.
  - paired bootstrap CIs (10k resamples) for loop − pipeline.
- Prompt tuning is allowed on the dev split only. Reported numbers are the test split.

## 3. Injection defenses
Gated by `INJECTION_DEFENSE` (default on) so the eval can measure before/after:
- A system-prompt rule: source and tool-result content is data, never instructions.
- A deterministic **tool-call guard**: `analyze_youtube_video` only for videos the *user* supplied
  (current message or earlier user turns, never model turns); `get_document` only for documents
  already seen in results or user-supplied videos; unknown tools refused.
- A deterministic **link sanitizer**: outside code spans, markdown images and links whose URL is
  not a retrieved source URL or a URL from the user's message lose the URL (images are removed).
- **Red-team eval**: 10 fixed attacks (canary insertion, authority spoofing, hidden comment, persona
  hijack, malicious link, image exfiltration, system-prompt leak, two tool hijacks, citation
  suppression) appended to a real retrieved passage, across 5 benign questions, against both
  the pipeline generator and the loop. Success is detected programmatically (canary string,
  forbidden domain, executed tool call). Report attack success rate with defense off vs on, plus
  a clean-run check that defended answers still cite sources.

## Decision rule (premium default)
Adopt `loop` as the premium default only if, on the test split:
- multi-hop correctness: loop − pipeline point estimate ≥ 0 and 95% CI lower bound ≥ −0.05, and
- v1 single-hop correctness: loop − pipeline 95% CI lower bound ≥ −0.05, and
- injection attack success rate with defense on: loop ≤ pipeline.

Otherwise the pipeline stays default and the loop ships as opt-in. Either way the README reports
the numbers, including any negative result.
